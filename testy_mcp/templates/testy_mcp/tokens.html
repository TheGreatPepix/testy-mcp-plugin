Что подставлять в конфиг

Одинаково для всех клиентов ниже:

TransportStreamable HTTP (JSON)
URL{{ mcp_endpoint }}
Заголовок Authorization: Token <ваш-токен>

Схема именно Token, а не Bearer. Не вставляйте токен в файлы, которые попадают в git: используйте переменную окружения или секрет клиента.

Подключение в агентах

Форматы сверены с документацией клиентов на октябрь 2026. Токен держите в переменной окружения TESTY_MCP_TOKEN, а не в файлах репозитория. Клиент без поддержки HTTP-заголовков подключается через мост mcp-remote в конце списка.

Claude Code 
claude mcp add --transport http --scope project testy {{ mcp_endpoint }}   --header "Authorization: Token ${TESTY_MCP_TOKEN}"

Команда записывает в проектный .mcp.json такой JSON (его же без изменений понимают многие другие клиенты). Поле "type": "http" обязательно: 

{
  "mcpServers": {
    "testy": {
      "type": "http",
      "url": "{{ mcp_endpoint }}",
      "headers": {
        "Authorization": "Token ${TESTY_MCP_TOKEN}"
      }
    }
  }
}

Не используйте для токена переменные вида ANTHROPIC_* или NPM_TOKEN: в заголовках удалённых серверов Claude Code подставляет их пустыми.

Claude Desktop

Settings → Connectors → Add custom connector: URL {{ mcp_endpoint }}, в «Request headers» заголовок Authorization: Token <ваш-токен>. Коннектор ходит в TestY из облака Anthropic, поэтому сервер должен быть доступен из интернета. Если TestY во внутренней сети, подключите его через mcp-remote (см. ниже) в claude_desktop_config.json.

OpenAI Codex (CLI и IDE)

В ~/.codex/config.toml. Переменная TESTY_MCP_AUTH содержит заголовок целиком: Token <ваш-токен>. Флаг --bearer-token-env-var не подходит: он отправляет схему Bearer. 

[mcp_servers.testy]
url = "{{ mcp_endpoint }}"
env_http_headers = { "Authorization" = "TESTY_MCP_AUTH" }
Cursor

Глобальный ~/.cursor/mcp.json (или проектный .cursor/mcp.json, если он в .gitignore):

{
  "mcpServers": {
    "testy": {
      "url": "{{ mcp_endpoint }}",
      "headers": {
        "Authorization": "Token ${env:TESTY_MCP_TOKEN}"
      }
    }
  }
}

Переменная должна быть задана в окружении, из которого запущен Cursor.

VS Code (GitHub Copilot)

Файл .vscode/mcp.json. Токен VS Code спросит один раз и сохранит в защищённом хранилище.

{
  "servers": {
    "testy": {
      "type": "http",
      "url": "{{ mcp_endpoint }}",
      "headers": {
        "Authorization": "Token ${input:testy-token}"
      }
    }
  },
  "inputs": [
    {
      "type": "promptString",
      "id": "testy-token",
      "description": "TestY MCP token",
      "password": true
    }
  ]
}
Gemini CLI 
gemini mcp add --transport http --header "Authorization: Token <ваш-токен>" testy {{ mcp_endpoint }}

Или вручную в settings.json; для Streamable HTTP нужно поле httpUrl, а не url:

{
  "mcpServers": {
    "testy": {
      "httpUrl": "{{ mcp_endpoint }}",
      "headers": {
        "Authorization": "Token <ваш-токен>"
      }
    }
  }
}
Другие клиенты: мост mcp-remote

Для клиентов, которые умеют только локальные stdio-серверы или не передают заголовки. Нужен Node.js. Двоеточие в Authorization:${...} без пробела — так аргумент не разрывается на Windows. 

{
  "mcpServers": {
    "testy": {
      "command": "npx",
      "args": [
        "mcp-remote",
        "{{ mcp_endpoint }}",
        "--header",
        "Authorization:${TESTY_MCP_AUTH_HEADER}"
      ],
      "env": {
        "TESTY_MCP_AUTH_HEADER": "Token <ваш-токен>"
      }
    }
  }
}

Как агент работает с TestY

Объяснять агенту ничего не нужно. Правила работы сервер передаёт сам: в инструкциях MCP и в описаниях инструментов. Там сказано, как сначала находить проект и набор по имени, запрашивать только нужные поля, создавать кейсы сразу со шагами, не перечитывать кейс после записи и ничего не удалять без вашего явного подтверждения. Достаточно сформулировать задачу, например: «В проекте TestY MCP добавь в набор „Установка плагина“ кейс на обновление плагина».
